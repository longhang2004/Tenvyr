# Tenvyr v0.1.0 commit plan

> Historical release record. Current release authority and publication blockers
> live in the [identity document](../../product/identity.md).

## Previous state and protection

The feature branch was already tracking a remote branch and therefore treated
as shared. Its five commits ahead of `main` mixed early platform work, fixes,
the private identity migration, and the Python Worker SDK. Rewriting or
force-pushing that history was rejected.

Before release preparation, recovery branch
`backup/tenvyr-v0.1.0-pre-release-20260728` was created at
`b6d2e12f4fb588ba4139af68b7d45bd04f41adde`. Recover without changing the active
checkout with:

```bash
git worktree add ../tenvyr-v0.1.0-recovery backup/tenvyr-v0.1.0-pre-release-20260728
```

## Strategy

- Branch shared: yes.
- Rewrite performed: no.
- Force-push: prohibited.
- Final branch history: existing commits plus the release-preparation changes;
  no artificial empty commits.
- Merge strategy: reviewed squash merge into `main` after required CI.
- Suggested squash message: `feat: prepare Tenvyr v0.1.0 showcase release`.

This produces one portfolio-readable integration commit without invalidating
the shared feature branch. The branch remains the detailed implementation
record until merged-main verification succeeds.

# T02 Task Report: Review Schema, Fixed Pipeline and Typed Shared Contracts

Status: **Accepted locally on 2026-11-14**. T00, T01, and T02 are the first
three accepted tasks. Authentication and review business routes remain later
work; this acceptance does not claim deployment or production readiness.

## Current implementation

- `ReviewTypes` contains the exact task records/enums, with copy-safe immutable
  lists for `Page.items` and `ReviewReport.findings`. The
  [interface handoff](../tasks/T02-review-schema.md#interfaces) is the shared
  contract for T03 actors, T04 reads/submission, and T05 report projection.
- `ReviewReportContract` requires integral score `0..100` without coercion,
  `0..50` nonblank findings of at most 1,000 UTF-16 code units each, and at most
  65,536 serialized UTF-8 bytes. Only score, findings, and optional object-valued
  `_tenvyr` are accepted. The separate schema documents Java's supplemental
  blank/UTF-16/serialized-byte checks; JSON Schema `maxLength` counts code points.
- Flyway V1 defines the five `tenvyr_review` tables and required indexes,
  idempotency constraints, code-byte bound, and three-language whitelist.
  Engine foreign keys explicitly address `public`. No mutable review-status
  shadow is stored; authentication and business operations remain later tasks.
- `PipelineCatalog.ensure` requires a caller transaction, locks the version
  binding, and reuses `PipelineService` on `Db.on(connection)`. It checks the
  binding hash, persisted schema version/content hash, and validated definition.
  Its fixed pipeline is `review-request-v1`, version `1`, one `review` step for
  `code-reviewer`, retries `2`, failure policy `retry`, timeout `30s`, and
  code/language templates. It does not commit or close the caller connection.
- Startup validates HTTP/no-Kafka configuration, runs retained base migrations,
  then Flyway, then catalog initialization in a single catalog transaction.
  `@DependsOnDatabaseInitialization` delays runtime construction until this
  completes; lifecycle phase 100 starts recovery before web admission.
  Lifecycle does not repeat migrations. Integration checks prove pooled sessions
  still address `public` after Flyway; no pool-wide reset loop is used.

## Verified behavior and handoff

The controller observed exact 65,536/65,537 report/code boundaries, valid
prerequisites for constraint failures with exact SQL states, exact index
ordering, unchanged 27 ledger identities, caller rollback ownership, and
persisted-definition/content-hash drift rejection.

Two real Spring applications start concurrently on an owned fresh database,
serve HTTP readiness, share one catalog binding/fixed pipeline, and retain
`public` pool paths. Invalid transport configuration fails before a base ledger
is created. An actual V1 duplicate-users-table migration error (`42P07`)
prevents runtime construction and readiness admission, and closes the pool.
The callback and lifecycle regressions remain covered in the same passing run.

The [exact DTO/catalog interfaces](../tasks/T02-review-schema.md#interfaces)
are ready for T03 actors, T04 requests/reads, and T05 reports. T03 must still
implement sessions, CSRF, and actor authorization; the schema alone does not
authenticate users. The controller records the local checkpoint after
documentation and identity verification, without pushing or publishing.

## Reproduce

Run from Ubuntu WSL2 Bash at the repository root. The following local fixture
commands load credentials from the ignored controller-owned file without
printing them; another environment must supply its own disposable database
credentials. The new runner and direct IT guard require a PostgreSQL JDBC URL
whose database name identifies a test/scratch/disposable database and reject
routing overrides and raw fragments.

```bash
sh scripts/review-checks.sh unit

. docs/_scratch/agy/T00/postgres.env
export POSTGRES_USER POSTGRES_PASSWORD
export TENVYR_REVIEW_TEST_DATABASE_URL='jdbc:postgresql://127.0.0.1:15432/tenvyr_review_test?sslmode=disable&currentSchema=public'
export JAVA_TOOL_OPTIONS=-Duser.timezone=UTC
sh scripts/review-checks.sh integration

sh scripts/backend-checks.sh pure
node scripts/verify-docs.mjs
node scripts/verify-product-identity.mjs
```

The full retained Kafka/polyglot compatibility suite remains a T08 gate.

## Delivered Architecture and Boundaries

1. **Review submission (`ReviewService.submit` & `POST /api/v1/reviews`):**
   - Enforces `SUBMITTER` role resolved from current session authentication via `ActorResolver`. `REVIEWER` role cannot submit and receives 403 `FORBIDDEN`.
   - Requires valid `Idempotency-Key` UUID header; rejects invalid/missing key with stable bounded 400 `BAD_REQUEST`.
   - Strict DTO duplicate/trailing/type checks: validates title trimmed 1..160 UTF-16 units; language exact `java`, `typescript`, or `python`; code nonblank up to 65,536 UTF-8 bytes; rejects duplicate keys, trailing content, and malformed types.
   - Computes canonical request hash `Json.hash({"title", normalizedTitle, "language", normalizedLanguage, "code", code})`.
   - Executes in a single Spring `TransactionTemplate` transaction on the SAME shared connection (`DataSourceUtils.getConnection`):
     - Sets local transaction timeouts: `SET LOCAL lock_timeout = '2s'`, `SET LOCAL statement_timeout = '5s'`.
     - Derives 64-bit advisory lock key from `(actorId, "SUBMIT", idempotencyKey)` and acquires `pg_advisory_xact_lock`.
     - Checks existing submission for `(owner_id, idempotency_key)`: equivalent payload returns 202 with original IDs; differing payload returns 409 `IDEMPOTENCY_CONFLICT`.
     - Loads fixed internal pipeline `review-request-v1` via `PipelineCatalog.ensure(conn)`.
     - Materializes engine execution via `engineRuntime.executions().materializeExecutionWithManager(conn, pipeline, input, now + 180s)`.
     - Invokes production-owned `PostMaterializationObserver` seam on the same connection.
     - Inserts request into `tenvyr_review.requests` and audit row into `tenvyr_review.audit` with action `SUBMIT`.
     - Releases connection without closing borrowed transaction handle; relies on existing runtime recovery to start executions after commit (no network call inside TX).
   - Maps database lock timeouts, deadlocks, and pool exhaustion to safe 503 `DATABASE_UNAVAILABLE` with `Retry-After: 1` header after rollback (never false permanent failure).

2. **Authorized bounded reads (`GET /api/v1/reviews` & `GET /api/v1/reviews/{id}`):**
   - SQL visibility enforcement: `SUBMITTER` sees only own requests; `REVIEWER` sees all requests. Foreign/invisible IDs return 404 `NOT_FOUND` consistently.
   - Keyset pagination sorted `createdAt DESC, id DESC`:
     - Cursor encoded as URL-safe Base64 of strict JSON `{createdAt, id}` bounded to <= 256 bytes.
     - Bounds limit between 1 and 100 (default 20).
     - Prepared SQL queries fetch `limit + 1` rows to calculate `nextCursor`.
     - Summaries strictly exclude source `code` and `report`.
   - Detail reading returns full source code only to authorized owner or reviewer.

3. **Strict report projection (`GET /api/v1/reviews/{id}/report`):**
   - Sourced strictly from verified `SUCCESS` attempt and `APPLIED` inbox row (actual persisted inbox status is `APPLIED`, not `COMMITTED`), checking payload hash and IDs.
   - Enforces business contracts via `ReviewReportMapper`: score 0..100, <= 50 findings, each nonblank <= 1000 units, report JSON <= 65,536 bytes.
   - Maps truthful metadata into `ReportEvidence`: `mode` (`MOCK` or `RUNNER`), `provider`, `model`, `fallbackUsed`, and `usageSource`.
   - Returns 200 OK with `ReviewReport` for completed valid reviews; returns 409 `REPORT_NOT_READY` if in progress; returns 409 `REVIEW_REPORT_INVALID` if terminal output violates contract.
   - Transient database read/write errors produce 503 `DATABASE_UNAVAILABLE` with `Retry-After: 1` after rollback, never false permanent report failure.

4. **Streaming body limit filter (`RequestBodyLimitFilter`):**
   - Filters only review business routes, preserving Spring form login and callback's own streaming bounds.
   - Enforces strict 1 MiB (1,048,576 bytes) boundary during streaming reads before JSON parsing or memory allocation. Returns 413 `PAYLOAD_TOO_LARGE` with stable bounded JSON error.

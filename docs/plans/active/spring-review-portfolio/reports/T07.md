## Delivered Architecture and Topology

1. **Self-contained Compose topology (`docker-compose.review.yml`):**
   - Strictly three container services: `review-api`, `review-worker`, and `postgres` under Compose project `tenvyr-review`.
   - `review-api` published strictly to loopback `127.0.0.1:8080`; `review-worker` and `postgres` are unpublished to host.
   - Worker operates in default `MOCK` mode with truthful metadata (no analysis, no paid calls).
   - Container labels: canonical Compose project `tenvyr-review` and `io.tenvyr.review.owner: "tenvyr-review"`.
   - API restart policy is `restart: "no"` to avoid first-bootstrap loops; `postgres` and `review-worker` use `restart: unless-stopped`.

2. **Launcher and smoke lifecycle (`scripts/review-showcase.sh`, `scripts/review-smoke.mjs`):**
   - Operations: `up`, `down`, `status` via `sh scripts/review-showcase.sh` and smoke via `node scripts/review-smoke.mjs`.
   - Private POSIX runtime directory (default `~/.tenvyr/review-runtime`, 0700/0600 modes); WSL `/mnt/c` and chmod 777 rejected.
   - Persistent volume `tenvyr_review_pgdata` preserves database state and credentials; missing state files fail closed.
   - Images built from committed Git archive source with `REVISION` metadata, independent of developer `target/` directories.
   - Bounded native Compose `--wait` and 3-user proof (`submitter_a`, `submitter_b`, `reviewer`) with CSRF, login, and identity verification.

3. **Review observability and metrics (`ReviewMetrics.java`):**
   - Strictly `health` and `metrics` endpoints exposed; public health `/actuator/health` provides minimal anonymous liveness/readiness.
   - Metrics RBAC on `/actuator/metrics` restricts access to `REVIEWER`, re-validating against fresh DB state (disabled 401, demoted 403).
   - Low-cardinality Timer `review.commands` tracks fixed command and outcome tags with 0.0 startup baseline; no sensitive labels.
   - Dynamic Backlog Gauge `review.backlog` counts current `AWAITING_REVIEW` requests with verified report; honest $N+1$ per-request scan ceiling noted.
   - Bounded capacity: Tomcat 50 threads / 50 accept-count, Hikari 10 connections / 2s timeout, Worker concurrency 2 / queue 16.
